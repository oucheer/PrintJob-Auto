# PrintCase Studio 0.4.0

**Excel 驱动的 Windows 打印用例执行平台**。把测试用例放进 Excel，软件负责用例解析、打印前检查、批量下发、Windows 队列关联、故障状态跟踪和执行报告导出。

> 当前版本是可运行的 Windows 桌面 MVP。它能核验“打印应用是否成功调用”和“Windows 打印队列/驱动反馈到什么状态”，不能仅凭队列状态证明纸张已从设备出纸。

## 1. 支持范围

- 操作系统：Windows 10 / Windows 11，需在已登录的交互式 Windows 用户会话运行。
- 用例清单：`.xlsx` / `.xlsm`；默认读取名为“用例”的工作表，否则读取第一个工作表。随软件提供的模板为全中文模板（字段名、示例与填写说明均为中文），同时兼容英文表头。
- 打印源文件：PDF、常见图片格式，以及 **Office 系列文档**：`docx` `doc` `rtf` `odt` `wps` `wpt`（用 Word/WPS 打开文档窗口后走 UI 自动化下发，不经转换）、`pptx` `ppsx` `pptm` `xls` `xlsx` `et` `ett`（先转 PDF 再由内置渲染器送入队列）。打印不依赖任何外部打印组件，属性由驱动属性页设置，文档由 Word/WPS 界面或内置渲染器（GDI + PDF 渲染）送入队列。
- 打印选项（下拉项与 Pantum CM806ADN 驱动属性页逐项对齐）：页码、份数（1–9999）、**纸张尺寸 17 种**（A4/A3/A5/JIS B4/JIS B5/JIS B6/Letter/Legal/Folio/Ledger/Executive/Statement/8K/Big16K/A6/A3Wide/SRA3，另有“自动”）、**混合尺寸开关（是/否）**、方向、颜色、单双面、**纸张来源 4 种**（自动选择/多功能进纸器/纸盒1/纸盒2）、**打印顺序（逐份/非逐份）**、**打印质量（600/1200）**、**纸张类型 10 种**、跳过空白页、**无边距（Y/N）**。打印机不设在表格里，统一在软件界面顶部选择；高级属性支持**无边距打印**、**分隔页（作业之间/份数之间，与驱动“纸张→输出→分隔页”一致，可指定分隔页纸张来源）**、**装订位置与装订方式**配置。打印前会尽力读取驱动公开的纸张、双面、颜色能力（驱动未提供能力数据时不会伪造结论）；**纸盒不在预检里按 DEVMODE 纸盒表判定**——该表常与属性页“纸张→来源”下拉对不上（本机实测属性页只有 自动选择/多功能进纸器/纸盒1/纸盒2，DEVMODE 却报 纸盒3/纸盒4/内置大容量纸盒），填错的纸盒会在驱动属性页按下拉实际条目报“下拉里没有 XX（可选：…）”。
- Office 文档打印原理：`docx` `doc` `rtf` `odt` `wps` `wpt` 由 Word/WPS 打开文档窗口，`Ctrl+P` 调出打印界面后选驱动并点“打印”（全程可见，日志逐步记录）；`pptx` `ppsx` `pptm` `xls` `xlsx` `et` `ett` 等 Word/WPS 打不开的格式先转 PDF 再由内置渲染器送入队列。打印属性处理、队列关联和状态跟踪对所有源格式保持一致。转换产生的临时 PDF 在该用例执行结束后自动删除。
- **下发方式（0.4 起只有一条通道，界面不再有模式切换）**：属性一律在**驱动自己的“打印首选项”**里设置，等价于用户手工点开首选项；设置完成后再下发文档。
  - 步骤 1／驱动属性页：打开“打印首选项” → 切到“基本/纸张/版面”页 → 按用例设置纸张尺寸、纸张类型、纸张来源、双面、颜色、打印质量、份数、逐份、无边距与扩展属性 → 点“确定”，由驱动自己保存。
  - 步骤 2／只读校验：重新读取打印机默认 DEVMODE，逐项比对（纸张尺寸/来源/双面/颜色/份数/打印质量比对代号；驱动私有介质要求“确实变化且非零”）。不一致的用例判定失败、不下发。
  - 步骤 3／提交文档：Word/WPS 能打开的文档走 UI 自动化（打开文档 → `Ctrl+P` → 选驱动 → 点“打印”）；PDF/图片没有文档界面，由内置渲染器送入同一打印队列。
  - 步骤 4／还原：用执行前的 DEVMODE 快照还原驱动默认值。
- 任务状态：检查通过/失败、下发中、队列中、驱动报告已打印、队列已清除（未证实出纸）、下发状态待核实、队列超时、失败。
- 执行顺序：串行；每条作业记录 Windows Job ID（若能关联）、时间、耗时、参数和错误信息。
- 审计：本机 SQLite 历史记录；本次执行结果可导出 CSV/JSON。

**打印链路（不依赖 SumatraPDF）**：docx/doc/rtf/odt/wps/wpt 由 Word/WPS 打开文档 → `Ctrl+P` → 在打印机下拉里选中目标驱动 → 点“打印”；PDF/图片由内置渲染器渲染后写入打印机队列；其余格式先转 PDF 再走同一条渲染链路。每个步骤（驱动属性页设置→回读校验→打开文档→选择驱动→下发→还原）都会实时显示在“执行日志”页。文字类文档无法用 Word/WPS 打开时才回退为转 PDF。本机既没有 Word/WPS 也没有 LibreOffice 时，Office 用例会在打印前检查阶段明确报错（并按格式提示缺哪个组件），不会静默失败。

## 2. 一键安装与启动（推荐）

1. 将整个 `PrintCaseStudio` 文件夹解压到本地磁盘（不要直接在 ZIP 压缩包内运行）。
2. 确保电脑首次安装时可以访问 Python 官方下载站与 PyPI/配置的镜像（打印已不依赖 SumatraPDF，无需下载）。
3. **双击 `Install_And_Run.bat`**。不需要手动打开 PowerShell，也不需要自己执行 pip 命令。

BAT 会自动执行以下步骤：

- 检测本机 Python 3.11–3.13；如果未找到，会尝试从 python.org 静默安装 Python 3.13.17（当前用户，无需管理员权限），下载失败时再尝试 Windows Package Manager（winget）。
- 创建当前项目专用的 `.venv`。若发现从另一台电脑复制过来的虚拟环境不可用，会将其备份并重新创建。
- 按 `requirements.txt` 安装并验证 `openpyxl`、`pywin32`、`PyInstaller`。默认 pip 源不可用时，依次尝试清华 TUNA、中科大和阿里云 HTTPS 镜像。
- 安装验证通过后自动启动 PrintCase Studio。

重复双击同一个 BAT 是安全的：已安装的 Python、依赖会复用；缺失或损坏的虚拟环境会自动修复。安装日志保存在 `logs/setup.log`。出现问题时，把该日志发给支持人员即可。

`run.bat` 也会执行相同的自检、补齐和启动流程。`setup_windows.ps1` 仅作为底层安装脚本保留，普通用户无需手动运行。

**网络说明：** Python 与 pip 依赖尚未作为完整离线安装包内置，因此第一次安装需要网络。企业网络若限制下载站点，需要使用企业批准的代理或软件源。没有网络时安装器会停止并保留日志，不会假装安装成功。

首次使用前建议先安装并配置打印机驱动，在 Windows“打印机和扫描仪”里确认能正常打印测试页。

### 驱动扩展属性表（移植自既有打印工具）

既有 print_panel 工具把驱动属性写成 `&属性名=值` 的多行文本塞进 9 列里，难以阅读和修改。本项目把它们改成一张**长表**，一行一个属性：

| 列 | 说明 |
|---|---|
| 用例编号 | 与“用例”表对应；同一用例可写多行 |
| 页面 | 下拉选择：WPS 页面布局 / Ctrl+P 打印页 / 驱动-基本 / 纸张 / 版面 / 水印 / 高级 / 密码/作业类型 / 封页 |
| 属性 | 下拉选择（60 项，与驱动界面文字一致） |
| 值 | 取值：0/1 勾选、选项文本、数字、文本，或 `宽*高`、`密码-作业名-用户名` 等复合值 |
| 说明 | 备注（可选） |

属性词表覆盖：多页合一、小册子、海报、省墨、旋转、缩放、镜像、无边距、偏移、混合尺寸、分隔页、OHP 插页、自定义纸张（名称/单位/长宽）、文本水印（内容/角度/字体/浓度/加粗/斜体/坐标）、TTF 位图打印、PDF 快捷打印、作业类型（普通/样本/延时/PIN 码打印）、封面封底（类型/纸盒）、装订（翻页/订钉/打孔/折叠）。

**但词表 ≠ 这台打印机真有的东西。** 本机驱动（Pantum M9705DN Plus-3700 Series）实测只有 7 个页签：基本、纸张、封页、版面、高级、背景画面、作业类型；**没有装订器相关控件**（翻页/订钉/打孔/折叠/接纸架/浓度都不存在）。用 `tools\audit_driver_options.py` 可以把驱动每个页签的控件与下拉条目完整导出来对照，写模板前先跑一遍：
- 用例表的 **装订位置 / 装订方式** 两列只做记录，不会下发（驱动没有对应控件）；
- 扩展属性里写了驱动没有的项（如 `装订设置-订钉`），执行时会明确报“找不到下拉框”，不会静默当成功。

**这些属性同样在驱动属性页里设置**（切到对应页签后按标签定位控件）；驱动界面里找不到对应选项时，用例判定失败且不下发。

**导入既有工具的用例**：直接导入其 `print.xlsx` 即可——软件识别 sheet `print` 里的 `&属性名=值` 文本块，自动转换为上表的扩展属性（用例编号=序号，标题=备注，打印文档路径=文件路径）。

## 4. 一次执行的推荐流程

1. 在 Windows 中确认目标打印机在线，纸张/纸盒/双面单元已正确配置。
2. 导入 Excel；选择默认打印机；逐条用例也可以覆盖默认打印机。
3. 点击“执行打印前检查”，修正文件路径、打印机名称、页码和参数错误。
4. 先勾选一条低风险用例试打（点击最左“选”列切换单条；表头“全选”复选框可一键全选/全不选，计数会同步显示“已选 N 条”），确认纸张、纸盒、方向和双面设置符合预期。
5. 再执行整批用例。软件串行下发，避免同时提交多条作业造成队列关联歧义。
6. 查看每条用例的 Windows Job ID、队列状态和诊断信息；导出 CSV/JSON 报告。

## 5. 状态语义与安全设计

- **已进入队列**：已在 Windows 队列中关联到作业，尚未证明打印完成。
- **驱动报告已打印**：驱动/队列设置了 `JOB_STATUS_PRINTED`，不等价于传感器证实出纸。
- **队列已清除（未证实出纸）**：之前观察到作业，随后作业从队列消失；不能推断物理输出成功。
- **已调用打印端（队列未关联）**：打印端返回成功，但软件没在观察窗口内关联到队列作业；应人工检查，不建议直接重试。
- **队列等待超时**：作业仍在队列，可能是离线、缺纸、暂停或设备处理缓慢。
- **下发失败**：打印组件返回失败，或队列报告错误。

不确定状态不会自动重试，避免重复打印。

**点“停止”会立即中止正在下发的那条用例**（文档还没点“打印”就直接收尾，界面一般 1–10 秒内回到可操作状态），后续用例标记为“已停止”不再下发。已经点过“打印”、作业进了 Windows 队列的不会被撤回，需要在队列里单独处理；状态栏会显示“已停止（按用户请求，剩余用例未下发）”。

**“点了打印却没出纸”如何被拦住**：Word 的后台打印视图里，“打印”按钮在预览渲染完成前是禁用的，此时点击不会报错也不会生效。旧版本把“点过按钮”直接当成“已提交”，随即关闭 Word——作业还没进队列就被一起结束，表现为“日志显示 3 条、实际只出来 2 份”。现在每次下发都按四步确认：

1. 等“打印”按钮真正变为可点击再点，点击后**确认打印视图关闭**（视图不动 = Word 没接受指令）；
2. 视图没关闭就在 6 秒后重点一次，两次都不接受则**判失败并明确说明**，不会记成已提交；
3. 关闭文档前等 Word 的后台打印任务**交接完成**，避免把还在排队的作业带走；
4. 队列关联不上时，日志里会带上监视器采样次数与失败次数，用于区分“队列里真没有作业”和“根本没读到队列”。

**停止/中断后马上再下发下一批**（常见操作：先勾 3 条试打，打了一条就点“停止”，接着勾另外 3 条继续），或者**跑完一轮后直接“执行全部”**：上一轮的驱动属性页、`printui` 宿主进程可能还挂在桌面上，或者驱动仍在收尾——此时新的 `printui /e` 会**静默退出、一个窗口都不建**，旧版本只能干等满超时再把用例判成“属性页窗口未出现”。现在按下面的顺序自愈：

1. 停止/失败的用例结束后立即清理残留的属性页窗口与 `printui` 进程（关不掉就结束该宿主进程）；
2. 每轮第一条用例设置属性前，再清一次上一轮可能留下的残留；
3. 上一件作业还在队列里时，先等它离开队列（最多 6 秒，日志会写明）；
4. 打开属性页时盯着 `printui` 进程：**秒退就立刻重试**（默认 4 次、合计约 40 秒，间隔 1.2/2.4/3.6 秒递增），已在桌面上的属性页会被直接复用；
5. **窗口是否出现改用 Windows 原生接口判断**，不再依赖 UI 自动化的全量窗口遍历。

第 5 条是关键：UI 自动化的桌面遍历在程序长时间运行、系统繁忙或驱动窗口刚创建时会整体失效（读不到窗口或直接报错）。这时属性页**其实已经打开**，旧实现却完全看不见它，于是白等一轮预算后把用例判成失败——这正是“只要点过停止，再下发就失败”“点执行全部失败”的真实原因（日志里表现为一次尝试干等到预算耗尽）。改用原生枚举后，同样状态下约 0.3 秒就能发现窗口并继续；即使 UI 自动化彻底不可用，报错也会明确写“属性页窗口已打开但读不到控件，请重启程序”，而不再误报成驱动没装。

日志里会看到“清理残留后重试（第 2/4 次）”这类记录，可以在“执行日志”页确认自愈过程。

**“停止后立刻再下发卡住 / 报未找到文档窗口”**：这是另一处同类问题——**文档窗口**的发现当时还在走 UI 自动化的桌面全量遍历。Word 其实已经打开、屏幕上看得见，遍历却读不到（或单次调用卡住十几秒），于是一路空等把用例超时（90 秒）耗光；用户看到的就是“点了停止之后，再下发一直转圈，最后失败”。现在文档窗口按下面的顺序找：

1. **Word/WPS 通过 COM 直接给出窗口句柄**（`Documents.Open` 返回后即可用，实测 0.0 秒）；
2. 拿不到就用 **Windows 原生 `EnumWindows` 按标题匹配**（毫秒级，能看到 UI 自动化漏掉的窗口），并优先本程序刚启动的那个实例；
3. 前两条都失败才低频回退到 UI 自动化遍历兜底。

另外，每个等待环节（等文档窗口、等打印界面、等“打印”按钮就绪、等后台任务交接）都会检查停止请求，点“停止”不再需要等满 90 秒；文档关闭改用“`Close` → `Quit` → 3 秒后仍未退出则结束本程序启动的那个 Word/WPS 实例”，避免残留窗口拖累下一次下发。

## 6. 打印参数边界

打印由内置直打引擎完成：页码选择、份数与逐份/非逐份在 GDI 通道按页精确控制，文字文档由 Word/WPS 的 PrintOut 传递份数与页码范围。模板已取消“缩放”列，统一按“适应页面”（fit）提交；如需“缩小/原始大小”，请在驱动中配置默认缩放。不同打印驱动对纸张名称、纸盒标识和双面单元的支持并不一致；安装后必须先用单条用例验证。

高级属性的能力边界说明：

- **混合尺寸打印**：把“混合尺寸”设为“是”时不向驱动强制指定纸张，按文档每页的纸张尺寸输出；此时纸盒只能是“自动选择”（驱动按页选择来源），填了具体纸盒会在检查阶段被拦截。能否正确出纸取决于驱动对混合介质的支持。
- **无边距打印**：在驱动属性页的“版面”页勾选“无边距”；驱动界面没有该选项时该用例判定失败不下发。
- **扩展属性**：水印、装订、作业类型、封页等 60 项驱动专属属性都在驱动属性页里设置；WPS 页面布局类属性（纸张方向/纸张大小/自定义纸）通过文档 COM PageSetup 设置，改版式后再下发。
- **分隔页（用例“分隔页”列）**：直接写驱动纸张页“输出→分隔页”的那一项，取值只有 **无 / 作业之间 / 份数之间**（真机下拉实测就这两项，没有“前/后/前后”，也不再由软件另打一张 PDF 充数）。两个前置条件缺一不可，软件已自动处理：①**纸张来源必须是具体纸盒**（“自动选择”时驱动把“输出/分隔页”整组灰化，点都点不动）；②要先选中“输出→分隔页”单选，下面的下拉才可用。所以“纸盒”填 自动选择 时写 作业之间/份数之间 会在打印前检查里直接报错；填 纸盒1/纸盒2 时软件自动切“输出→分隔页”再选值，并回读确认。**份数为 1 时“份数之间”不会产生分隔页**，执行日志会提示。
- **分隔页纸张来源（用例同名列）**：写驱动“分隔页”下面那行的“纸张来源”（分隔纸从哪个纸盒取）。留空则沿用驱动当前值；分隔页=无 时必须留空（该行灰化）。
- **“分隔页=无”会显式把“输出”切回“正常”**：驱动默认设置是全局的，上一轮跑过 作业之间 之后会留在那个状态；不显式关掉，下一条用例会莫名多出一张分隔页。
- **表格不做灰度提示**：互斥关系不在表格里做视觉禁用，改由“打印前检查”统一拦截并给出具体原因：混合尺寸=是 → 纸张列忽略且纸盒必须自动选择；纸张类型=信封纸/明信片/标签纸/透明胶片 → 不能双面；分隔页=无 → 不能填分隔页纸张来源；装订位置=长边/短边 → 必须双面。
- **属性生效保证（严格模式）**：打印顺序（逐份/非逐份）、打印质量（600/1200）、纸张尺寸、纸张类型、纸张来源、双面、颜色、份数都在驱动属性页里设置，并在“确定”之后**只读回读**驱动默认 DEVMODE 逐项核对。出现以下情况时用例**判定失败、不下发打印**：①驱动界面里找不到用例要求的选项（如驱动未上报“厚纸9”这类介质）；②回读值与要求不一致（驱动悄悄还原或改写）。这样不会出现“属性没生效但作业照常打印”的假结果。整个窗口期用的是打印机全局默认设置，本机其他程序同时打印也会受影响（软件串行执行把窗口期压到最短），用例结束后立即用快照还原。
  - **例外（目标值恰为驱动默认值）**：纸张尺寸/纸张类型/纸张来源这类私有不透明编码，若用例要求的值本来就和驱动当前默认值相同（例如“普通纸”就是驱动默认），设置后 DEVMODE 自然不变。此时软件在设置前读取驱动界面当前选中项，确认已是目标项后按“无需变更”处理并通过校验，不会把正常情况误判为失败。
- **仅记录意图、按驱动默认执行的属性**：跳过空白页——驱动私有设置，标准 DEVMODE 与命令行均无法指定；如需固定，请在驱动“快速设置”中保存为默认。
- **暂不支持的厂商私有功能**：样本打印/延时打印/PIN 码打印（作业类型）、偏移输出、以黑色打印文本、OHP 插页，均为驱动私有 DEVMODE 选项；如需测试这些项，请在驱动端配置默认值后执行，并在“备注”列记录预期。

### 驱动属性页自动化的能力与边界

- 适用于 `docx doc rtf odt wps wpt`（需要 Word 或 WPS）；PDF/图片没有可自动化的文档界面，会自动回落到内置 GDI 直打，日志中会注明。
- 属性通过驱动属性页真实设置：纸张尺寸、纸张类型、纸张来源、双面、颜色、打印质量、份数、逐份、无边距、扩展属性。**用例显式填写但驱动界面里找不到对应选项时，用例判定失败且不下发**。
- 控件识别采用“页签＋位置＋标签”多重匹配：多数厂商驱动（含 Pantum）把页签标签错位挂到下一个控件上，而且下拉项是自绘的、UIA 读不到条目文本，因此下拉按下标定位（`Home` + 方向键），再用回读代号验证；不同品牌驱动差异较大，建议先用一条用例验证，必要时点界面上的“自检驱动属性页”。
- UI 自动化期间请勿手动操作鼠标键盘，避免打断对话框操作。
- **属性页打不开（“驱动‘打印首选项’窗口未出现”）**：先看日志里是否出现“清理残留后重试”。软件会自动清理残留窗口/进程并重试 3 次；失败信息里会带上每次尝试的原因（例如“启动的 printui 进程已退出，且没有创建任何窗口”）。若三次都失败，通常是驱动安装异常、打印机被其他程序长期占用，或需要等队列清空后再试。
- **为什么不再直接写 DEVMODE**：多数驱动把克重介质、专有纸盒等编码成私有不透明 DWORD，`DC_MEDIATYPES` 上报的值甚至每次调用都不同（实测同一台 Pantum 连续两次返回不同值），外部写死数值无法保证指向正确介质；而驱动界面里的下拉顺序是稳定的。把翻译工作交回驱动，只在旁边做只读校验，才能既真实又可控。
- **报“无法在设置线程模式后对其加以更改”（WinError -2147417850）怎么办**：这不是“选不了驱动”，而是 COM 单元（apartment）冲突——同一线程里 Word/WPS 的 COM 已按 STA 初始化，而 pywinauto/comtypes 默认要 MTA。软件已把 UI 引擎的导入与自检放到独立线程，并按线程真实单元模式设置 `coinit_flags`（见 `src/printcase/cominit.py`）；若仍然报错，先完全退出残留的 Word/WPS 进程再重试一次。

### 执行日志落盘

界面上的“执行日志”只在内存里，程序关闭即丢失。现在每次运行会同时写入
`%LOCALAPPDATA%\PrintCaseStudio\logs\RUN-<时间>-<RUNID>.log`（保留最近 40 份），
日志页右上角有“打开日志目录”按钮。下发失败后可以把这份文件直接发给维护者排查。

实测记录：
- `--to-file`：完整链路（驱动属性页设置→渲染 PDF→提交→还原）产出可用的 PDF，StartDoc 返回队列作业号。
- 目标打印机不可用/驱动拒绝时，软件会**如实报告失败**（例如“StartDoc 失败，错误码…”），不会伪装成功。
- Word 2013+ 的 `Ctrl+P` 是后台打印视图（非独立对话框）：识别后台视图 → 打印机下拉里点选目标驱动 → 点“打印”；驱动属性已在步骤 1 设置并校验，这里只负责提交。
- Word 冷启动时焦点可能还没落到正文上，首次 `Ctrl+P` 会被吞掉：程序会先把焦点点进正文（并清除“受保护的视图/启用编辑”横幅）再发送，未出现打印界面时重新聚焦重试（最多 6 次、每次约 8 秒），不会一次失败就空等到超时。批量下发时首条用例因此不会再莫名失败。
- 队列监视在下发**之前**就以约 0.08 秒间隔采样并留档，作业在队列里只存活几百毫秒也能被捕获；批量串行下发时每条用例各自关联到自己的作业号，不会串作业。

## 9. 已知限制 / 下一阶段

- 仅在 Windows 上执行真实打印；Linux/macOS 只能运行核心单元测试。
- 当前没有接入厂商私有 SNMP/MIB、IPP 扩展、打印机内置计数器、出纸传感器，因此不提供物理出纸/卡纸位置的确定性判断。
- 作业快速完成、驱动改写作业文档名或后台清理时，可能无法安全关联 Job ID；软件不会仅凭“队列里恰好多了一条作业”猜测归属，此时显示“队列未关联”，避免把其他应用的打印任务误认成本用例。
- 当前不做无人值守服务运行，不在 SYSTEM 账户或 Session 0 中打印。
- 当前不对打印内容正确性、二维码可读性、颜色精度、缺页/重页作视觉验收。

下一阶段建议：更细粒度的驱动能力探测与参数模板、品牌驱动配置插件、打印机池/多设备批量调度、IPP/SNMP 设备健康监控、摄像头/传感器出纸确认、打印内容视觉质检、测试报告基线对比。

# PrintCase Studio 0.3.1

**Excel 驱动的 Windows 打印用例执行平台**。把测试用例放进 Excel，软件负责用例解析、打印前检查、批量下发、Windows 队列关联、故障状态跟踪和执行报告导出。

> 当前版本是可运行的 Windows 桌面 MVP。它能核验“打印应用是否成功调用”和“Windows 打印队列/驱动反馈到什么状态”，不能仅凭队列状态证明纸张已从设备出纸。

## 1. 支持范围

- 操作系统：Windows 10 / Windows 11，需在已登录的交互式 Windows 用户会话运行。
- 用例清单：`.xlsx` / `.xlsm`；默认读取名为“用例”的工作表，否则读取第一个工作表。随软件提供的模板为全中文模板（字段名、示例与填写说明均为中文），同时兼容英文表头。
- 打印源文件：PDF、常见图片格式，以及 **Office 系列文档**：`docx` `doc` `rtf` `odt` `wps` `wpt`（Word/WPS COM **直接打开原文档打印**，不经转换）、`pptx` `ppsx` `pptm` `xls` `xlsx` `et` `ett`（先转 PDF 再直打）。打印不依赖任何外部打印组件，全部由内置直打引擎（GDI + PDF 渲染）与 Office/WPS COM 完成。
- 打印选项（下拉项与 Pantum CM806ADN 驱动属性页逐项对齐）：页码、份数（1–9999）、**纸张尺寸 17 种**（A4/A3/A5/JIS B4/JIS B5/JIS B6/Letter/Legal/Folio/Ledger/Executive/Statement/8K/Big16K/A6/A3Wide/SRA3，另有“自动”）、**混合尺寸开关（是/否）**、方向、颜色、单双面、**纸张来源 4 种**（自动选择/多功能进纸器/纸盒1/纸盒2）、**打印顺序（逐份/非逐份）**、**打印质量（600/1200）**、**纸张类型 10 种**、跳过空白页、**无边距（Y/N）**。打印机不设在表格里，统一在软件界面顶部选择；高级属性支持**无边距打印**、**分隔页**（前/后/前后/份数之间，可指定分隔页纸张来源）、**装订位置与装订方式**配置。打印前会尽力读取驱动公开的纸张、双面、颜色和纸盒能力；驱动未提供能力数据时不会伪造结论。
- Office 文档打印原理：`docx` `doc` `rtf` `odt` `wps` `wpt` 由 Word→WPS COM **直接打开原文档打印**（不经转换）；`pptx` `ppsx` `pptm` `xls` `xlsx` `et` `ett` 等 Word/WPS 打不开的格式先转 PDF 再由内置 GDI 引擎直打。打印属性处理、队列关联和状态跟踪对所有源格式保持一致。转换产生的临时 PDF 在该用例执行结束后自动删除。
- **下发方式（界面顶部切换，两种模式并存）**：
  - **直接驱动（推荐，默认）**：Word/WPS COM 打开文档并用 `ActivePrinter` 选择驱动 + `PrintOut` 下发；PDF/图片由内置 GDI 引擎直写打印机队列，全程无界面。
  - **UI 自动化（pywinauto）**：真正“操控电脑”的方式——打开文档窗口 → 发送 `Ctrl+P` 调出打印对话框 → 选择打印机下拉 → 填份数/页码范围 → 点“首选项”进入驱动属性页 → 按用例设置纸张/纸盒/双面/质量/无边距 → 确定 → 点击“打印”。全程窗口可见，每一步都写进执行日志。
- 任务状态：检查通过/失败、下发中、队列中、驱动报告已打印、队列已清除（未证实出纸）、下发状态待核实、队列超时、失败。
- 执行顺序：串行；每条作业记录 Windows Job ID（若能关联）、时间、耗时、参数和错误信息。
- 审计：本机 SQLite 历史记录；本次执行结果可导出 CSV/JSON。

**打印链路（不依赖 SumatraPDF）**：docx/doc/rtf/odt/wps/wpt 由 Word→WPS COM **直接打开文档 → 设置 ActivePrinter 选择驱动 → 按用例属性 PrintOut 下发**；PDF/图片由内置 GDI 引擎渲染后直接写入打印机队列；其余格式先转 PDF 再 GDI 直打。每个步骤（写驱动属性→打开文档→选择驱动→下发→恢复默认）都会实时显示在“执行日志”页。文字类文档无法用 Word/WPS 打开时才回退为转 PDF。本机既没有 Word/WPS 也没有 LibreOffice 时，Office 用例会在打印前检查阶段明确报错（并按格式提示缺哪个组件），不会静默失败。

## 2. 一键安装与启动（推荐）

1. 将整个 `PrintCaseStudio` 文件夹解压到本地磁盘（不要直接在 ZIP 压缩包内运行）。
2. 确保电脑首次安装时可以访问 Python 官方下载站与 PyPI/配置的镜像（打印已不依赖 SumatraPDF，无需下载）。
3. **双击 `Install_And_Run.bat`**。不需要手动打开 PowerShell，也不需要自己执行 pip 命令。

BAT 会自动执行以下步骤：

- 检测本机 Python 3.11–3.13；如果未找到，会尝试从 python.org 静默安装 Python 3.13.17（当前用户，无需管理员权限），下载失败时再尝试 Windows Package Manager（winget）。
- 创建当前项目专用的 `.venv`。若发现从另一台电脑复制过来的虚拟环境不可用，会将其备份并重新创建。
- 按 `requirements.txt` 安装并验证 `openpyxl`、`pywin32`、`PyInstaller`。默认 pip 源不可用时，依次尝试清华 TUNA、中科大和阿里云 HTTPS 镜像。
- 安装验证通过后自动启动 PrintCase Studio。

重复双击同一个 BAT 是安全的：已安装的 Python、依赖会复用；缺失或损坏的虚拟环境会自动修复。安装日志保存在 `logs/setup.log`。出现问题时，把该日志发给支持人员即可。

`run.bat` 也会执行相同的自检、补齐和启动流程。`setup_windows.ps1` 仅作为底层安装脚本保留，普通用户无需手动运行。

**网络说明：** Python 与 pip 依赖尚未作为完整离线安装包内置，因此第一次安装需要网络。企业网络若限制下载站点，需要使用企业批准的代理或软件源。没有网络时安装器会停止并保留日志，不会假装安装成功。

首次使用前建议先安装并配置打印机驱动，在 Windows“打印机和扫描仪”里确认能正常打印测试页。

### 驱动扩展属性表（移植自既有打印工具）

既有 print_panel 工具把驱动属性写成 `&属性名=值` 的多行文本塞进 9 列里，难以阅读和修改。本项目把它们改成一张**长表**，一行一个属性：

| 列 | 说明 |
|---|---|

| 说明 | 备注（可选） |

覆盖的驱动能力包括：多页合一、小册子、海报、省墨、浓度、旋转、缩放、镜像、无边距、装订（翻页/订钉/打孔/折叠/张数）、接纸架、偏移、混合尺寸、分隔页、OHP 插页、自定义纸张（名称/单位/长宽）、文本水印（内容/角度/字体/浓度/加粗/斜体/坐标/动态水印）、水印选择与删除、TTF 位图打印、PDF 快捷打印、作业类型（普通/样本/延时/密码打印）、封面封底（类型/纸盒）。

## 4. 一次执行的推荐流程

1. 在 Windows 中确认目标打印机在线，纸张/纸盒/双面单元已正确配置。
2. 导入 Excel；选择默认打印机；逐条用例也可以覆盖默认打印机。
3. 点击“执行打印前检查”，修正文件路径、打印机名称、页码和参数错误。
4. 先选中一条低风险用例试打，确认纸张、纸盒、方向和双面设置符合预期。
5. 再执行整批用例。软件串行下发，避免同时提交多条作业造成队列关联歧义。
6. 查看每条用例的 Windows Job ID、队列状态和诊断信息；导出 CSV/JSON 报告。

## 5. 状态语义与安全设计

- **已进入队列**：已在 Windows 队列中关联到作业，尚未证明打印完成。
- **驱动报告已打印**：驱动/队列设置了 `JOB_STATUS_PRINTED`，不等价于传感器证实出纸。
- **队列已清除（未证实出纸）**：之前观察到作业，随后作业从队列消失；不能推断物理输出成功。
- **已调用打印端（队列未关联）**：打印端返回成功，但软件没在观察窗口内关联到队列作业；应人工检查，不建议直接重试。
- **队列等待超时**：作业仍在队列，可能是离线、缺纸、暂停或设备处理缓慢。
- **下发失败**：打印组件返回失败，或队列报告错误。

不确定状态不会自动重试，避免重复打印。停止操作只停止后续下发；已经进入打印队列的作业需要在 Windows 队列中单独处理。

## 6. 打印参数边界

打印由内置直打引擎完成：页码选择、份数与逐份/非逐份在 GDI 通道按页精确控制，文字文档由 Word/WPS 的 PrintOut 传递份数与页码范围。模板已取消“缩放”列，统一按“适应页面”（fit）提交；如需“缩小/原始大小”，请在驱动中配置默认缩放。不同打印驱动对纸张名称、纸盒标识和双面单元的支持并不一致；安装后必须先用单条用例验证。

高级属性的能力边界说明：

- **混合尺寸打印**：把“混合尺寸”设为“是”时不向驱动强制指定纸张，按文档每页的纸张尺寸输出；此时纸盒只能是“自动选择”（驱动按页选择来源），填了具体纸盒会在检查阶段被拦截。能否正确出纸取决于驱动对混合介质的支持。
- **无边距打印**：直接驱动模式下打印接口没有无边距开关，软件会记录该属性并提示先在驱动首选项中配置；**UI 自动化模式会直接在驱动属性页勾选“无边距”**，无法定位时该用例判定失败不下发。
- **扩展属性**：水印、装订、作业类型、封页等 60 项驱动专属属性仅 UI 自动化模式支持；WPS 页面布局类属性（纸张方向/纸张大小/自定义纸）通过文档 COM PageSetup 设置，改版式后再下发。
- **分隔页**：由软件在主作业前/后、或每份之间生成并下发独立的间隔页 PDF（可指定分隔页纸盒）。“份数之间”模式按单份逐个下发主文档，保证分隔页准确插入每份之间；属“作业间隔页”，不是打印机硬件分隔页，也不能选择 OHP 插页等介质类型。
- **装订属性**：装订位置为长边/短边时强制对应双面模式（校验不通过会明确报错）；左/右/上/下位置和订书钉、骑马钉、打孔、胶装等装订方式依赖驱动与选购装订器，软件记录意图并写入审计日志，不承诺硬件行为。
- **表格不做灰度提示**：互斥关系不在表格里做视觉禁用，改由“打印前检查”统一拦截并给出具体原因：混合尺寸=是 → 纸张列忽略且纸盒必须自动选择；纸张类型=信封纸/明信片/标签纸/透明胶片 → 不能双面；分隔页=无 → 不能填分隔页纸张来源；装订位置=长边/短边 → 必须双面。
- **通过 DEVMODE 真实生效的属性（严格保证）**：打印顺序（逐份/非逐份）、打印质量（600/1200）、纸张类型、纸张尺寸（全部显式尺寸）、纸张来源（名称类纸盒 → DefaultSource）。这些属性无法随文档传递，软件会在该用例下发前**临时写入打印机驱动默认 DEVMODE**，写入后**回读校验**确认驱动真的接受了设置；出现以下任一情况时用例**直接判定失败、不下发打印**：①显式填写的属性在驱动中解析不到代号（如驱动未上报“厚纸2”的介质代号）；②写入后回读不一致（驱动悄悄还原）。这样保证不会出现“属性没生效但作业照常打印”的假结果。写入的属性在用例结束后自动恢复原值。注意写入期间这是打印机全局默认设置，本机其他程序同时打印也会受影响（软件串行执行把窗口期压到最短）。
- **仅记录意图、按驱动默认执行的属性**：跳过空白页——驱动私有设置，标准 DEVMODE 与命令行均无法指定；如需固定，请在驱动“快速设置”中保存为默认。
- **暂不支持的厂商私有功能**：样本打印/延时打印/PIN 码打印（作业类型）、偏移输出、以黑色打印文本、OHP 插页，均为驱动私有 DEVMODE 选项；如需测试这些项，请在驱动端配置默认值后执行，并在“备注”列记录预期。

### UI 自动化模式的能力与边界

- 适用于 `docx doc rtf odt wps wpt`（需要 Word 或 WPS）；PDF/图片没有可自动化的文档界面，会自动回落到内置 GDI 直打，日志中会注明。
- 属性通过驱动属性页真实设置：纸张尺寸、纸张类型、纸张来源、双面、打印质量、无边距、份数、页码范围。**用例显式填写但驱动界面里找不到对应选项时，用例判定失败且不下发**（与直接驱动模式的严格策略一致）。
- 依赖控件文案识别（“纸张尺寸/Paper Size”“首选项/Preferences”等中英文常见写法）。不同品牌驱动的对话框布局差异较大，建议先用一条用例验证；若某个驱动识别不到，可改用直接驱动模式。
- UI 自动化期间请勿手动操作鼠标键盘，避免打断对话框操作。
- **为什么会有两种下发方式**：直接驱动不依赖 Office，适合 PDF/图片与批量静默用例，但只能改标准 DEVMODE；UI 自动化走驱动自己的属性页，真实等价于用户手工操作，适合验证驱动专属属性（水印/装订/作业类型等 60 项），但只支持 Office 文档且较慢。两者是互补关系，不建议只留一种。
- **报“无法在设置线程模式后对其加以更改”（WinError -2147417850）怎么办**：这不是“选不了驱动”，而是 COM 单元（apartment）冲突——同一线程里 Word/WPS 的 COM 已按 STA 初始化，而 pywinauto/comtypes 默认要 MTA。软件已把 UI 引擎的导入与自检放到独立线程，并按线程真实单元模式设置 `coinit_flags`（见 `src/printcase/cominit.py`）；若仍然报错，先完全退出残留的 Word/WPS 进程再切换一次下发方式。

## 7. 打包成 EXE（开发者可选）

普通用户无需执行此步骤。开发者在完成一键安装后，可运行：

```powershell
.\build_windows.ps1
```

产物在 `dist/PrintCaseStudio.exe`（含模板与说明资源，打印无需任何外部组件）。

**分发给其他用户**：把整个 `dist` 文件夹复制（或压缩）给对方即可，目标机器**无需安装 Python、依赖或整个仓库**，双击 `PrintCaseStudio.exe` 直接运行；首次使用需确认 Windows 打印服务与打印机驱动已装好。打印链路完全内置：EXE 单文件即可下发打印。Office 文档（docx/doc/rtf/odt/wps/pptx/xls 等）需要目标机器安装有 Word、WPS 或 LibreOffice 三者之一（顶部“文档转换”标签会显示检测到的组件）；纯 PDF/图片用例无任何额外要求。exe 更新时只需替换 `PrintCaseStudio.exe`。

## 8. 自测与验证（tools/smoke_e2e.py）

```text
# 真实下发到打印机（会真的出纸/进队列）
.venv\Scripts\python.exe tools\smoke_e2e.py --mode direct
.venv\Scripts\python.exe tools\smoke_e2e.py --mode ui

# 无硬件也能验证整条链路：打印到文件（Microsoft Print to PDF）
.venv\Scripts\python.exe tools\smoke_e2e.py --mode direct --to-file dist\smoke-output.pdf
```

脚本把前端“执行日志”页会收到的每一行事件原样打印，并输出状态、关联 Job ID、队列新增作业和输出文件大小。

实测记录：
- `--mode direct --to-file`：完整链路（写驱动属性→渲染 PDF→GDI 提交→恢复）产出 92 KB PDF，StartDoc 返回队列作业号。
- 目标打印机不可用/驱动拒绝时，软件会**如实报告失败**（例如“StartDoc 失败，错误码…”），不会伪装成功。
- Word 2013+ 的 `Ctrl+P` 是后台打印视图（非独立对话框），UI 自动化已适配：识别后台视图→选择打印机→点“打印机属性”（找不到时回退 DEVMODE 已确认的标准属性）→ 点击“打印”。

## 9. 已知限制 / 下一阶段

- 仅在 Windows 上执行真实打印；Linux/macOS 只能运行核心单元测试。
- 当前没有接入厂商私有 SNMP/MIB、IPP 扩展、打印机内置计数器、出纸传感器，因此不提供物理出纸/卡纸位置的确定性判断。
- 作业快速完成、驱动改写作业文档名或后台清理时，可能无法安全关联 Job ID；软件不会仅凭“队列里恰好多了一条作业”猜测归属，此时显示“队列未关联”，避免把其他应用的打印任务误认成本用例。
- 当前不做无人值守服务运行，不在 SYSTEM 账户或 Session 0 中打印。
- 当前不对打印内容正确性、二维码可读性、颜色精度、缺页/重页作视觉验收。

下一阶段建议：更细粒度的驱动能力探测与参数模板、品牌驱动配置插件、打印机池/多设备批量调度、IPP/SNMP 设备健康监控、摄像头/传感器出纸确认、打印内容视觉质检、测试报告基线对比。
